| R10 | Cutscenes (the intro, the launch) lag | CAUSE FOUND in the machine, not the pictures (1 Nov 11:30); fix belongs to the P2 session | Measured with the new `F117_LOOP_TIMING=1` (a line every 2 s: wall time in the machine, in present, hooks, and where slow slices end). Original, Enhanced and Remastered all lose the same real time in the same places (about 205 M of the first 1.1 G clocks are discarded in each; sound makes no difference, speaker or AdLib; the hooks cost 0 ms). In the intro (wall 8 to 19 s, clocks 0.4 G to 0.9 G of the owner's session) the machine runs at about 40 M clocks a second against the 60 M it needs, where normal stretches run about 220 M. About 990 of the slow slices end at `0060:00C4`: the `LOOP $` of the DOS-call overhead stub (DOSBox's CB overhead for INT 21h 06h, 0Bh and 2Ch: `PUSH CX; MOV CX,140h; LOOP $; POP CX; IRET`, `src/machine/dos.c` `STUB_OVERHEAD`), i.e. the game polls DOS in a loop and the machine spends 320 instructions in that stub on every poll, each far slower than a normal instruction. So the music (driven by the machine's clock) lags with the picture, which also explains S1's "choppy" Roland intro. Fix for the P2 session (it is the machine core, which this session stays out of): run the stub's `LOOP $` as one step that charges the same instruction count, or find why an instruction there costs five times the usual host time. Parity must hold: the same clocks, the same state after the stub. |
